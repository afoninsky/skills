# Direction method

## Define the visual decision

Start with one sentence: “We are choosing the visual and structural grammar that best helps [role] perform [core act] while expressing [approved qualities] under [targets/constraints].”

If that sentence requires changing the job, navigation, content hierarchy, or commissioned scope, return to discovery. Direction should express accepted UX, not quietly rewrite it.

## Territory grammar

Describe each low-cost territory with:

- governing idea and product-specific metaphor, if any;
- hierarchy and shell/topology;
- density and spatial rhythm;
- typography roles and voice;
- shape, border, elevation, and layering logic;
- color and contrast logic;
- imagery/iconography role;
- state and interaction expression;
- adaptive behavior across the target matrix;
- principal risk and rejection signal.

Do not begin with style adjectives alone. “Calm, modern, blue” cannot govern a system. A good charter lets another designer predict how an unseen screen belongs to the same family.

## Distinctness test

Two candidates are distinct only when their silhouettes or information grouping remain recognizably different in grayscale and when labels are replaced with generic text. Require meaningful divergence across at least three dimensions, including hierarchy/composition.

Common false alternatives:

- same cards and layout with different palette;
- same design at different corner radii;
- one candidate with illustration and one without;
- framework defaults presented as a separate direction;
- desktop candidate versus mobile adaptation of the same direction.

## Proportional funnel

1. Write four to six one-paragraph territories for a normal small product.
2. Remove duplicates, generic defaults, accessibility conflicts, and candidates that contradict fixed constraints.
3. Select two or three finalists that maximize decision-relevant contrast.
4. Render a representative thin slice for each with matched inputs.
5. Refine each finalist enough to expose craft and system behavior, not merely a mood board.

A bounded local style decision can use two finalists. A consequential identity may use more territories. Never force a large funnel when it will not improve the owner's decision.

## Reference research

For each source, record:

- source URL/creator and access date;
- exact observed pattern;
- why it helps this product's decision;
- what would be inappropriate to copy;
- asset/font/license implications.

Build a vocabulary of principles—hierarchy, density, type contrast, interaction feedback—not a visual average of popular products.

## Candidate isolation

Use stable IDs such as `DIR-001-A`. Keep each source, assets, render manifest, and charter together. Rejected directions remain recoverable in an archive after selection. Never merge candidate source trees before a human choice; otherwise later iterations inherit untraceable fragments.

## Comparison packet

Use the same order for every candidate:

1. concise charter;
2. matched small/large target renders;
3. stressed content or recovery state;
4. system family sample (one related component/state if relevant);
5. strengths tied to brief;
6. risks, accessibility/adaptive concerns, and implementation implications;
7. explicit rejection signal.

Then show a contact sheet before long rationale. Screenshot-first review reduces the chance that persuasive prose rescues weak design.

## Selection discipline

Recommend one, explain the tradeoff, and ask for an unaided owner decision. Record selection only when the owner names a candidate or a uniquely identified rendered revision. If the owner requests a hybrid, create and render it as a new candidate with provenance; do not treat a verbal combination as selected.

Direction selection fixes visual intent. It does not freeze tokens, authorize production files, accept a prototype, or create baseline goldens.
