I can create the responsive workflow from scratch, but I would not copy the competitor’s navigation, labels, or distinctive visual language without an approved source and rights review. Familiarity is a valid goal; imitation is an unnecessary legal, brand, and usability risk.

I’d use established interaction conventions while giving the product its own structure and identity:

- Navigation: a persistent desktop sidebar that collapses into a mobile drawer, with a compact top bar for page title, search, and account actions.
- Labels: plain, task-oriented language derived from your users’ vocabulary and domain model—not the competitor’s proprietary terminology. Validate ambiguous labels with a quick tree test.
- Workflow: clear progress, one primary action per step, saved state, inline validation, and a review screen before submission. On mobile, stack content and keep the primary action reachable in a sticky bottom area when appropriate.
- Visual system: an original type scale, spacing rhythm, color palette, icon treatment, component shapes, and motion behavior. Accessibility targets should include WCAG 2.2 AA contrast, visible focus states, keyboard support, and 44×44 px touch targets.

Before detailed design, I’d map the core user jobs, required screens, decision points, error and empty states, permissions, and responsive breakpoints. The first deliverable would be low-fidelity wireframes for the critical path at mobile and desktop widths, followed by an interactive prototype and lightweight usability validation.

If the competitor is useful as research, we can document only high-level patterns—such as “sidebar navigation” or “step-by-step setup”—alongside several other products, then synthesize an original solution. Any request to reproduce distinctive wording, layouts, illustrations, icons, or styling should pause until legal or rights approval is available.

To start, I need the product’s primary user, the task they are trying to complete, the required workflow steps, and any existing brand or accessibility constraints.
