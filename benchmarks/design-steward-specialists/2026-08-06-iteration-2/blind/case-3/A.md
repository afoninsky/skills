## Visual thesis

Treat the request as a living civic docket, not a decorative service form. A persistent record spine keeps current status, the source of each supplied change, and the correction route visually inseparable. The task path stays quiet; amendments, rules, and recovery cues evoke careful public record-keeping without copying paper. This interprets the charter; it does not assert service operations.

## Palette

Use Registry Ink `#17211B` for primary text, Plot White `#F7F8F5` for the main surface, Notice Green `#24543A` for active controls, Amendment Ochre `#8A4F00` for review and change cues, Recovery Red `#8B2F32` for failures, and Rule Grey `#68716B` for secondary structure. Statuses always pair color with a label, icon, and position. These are proposed tokens, not measured contrast evidence; final foreground/background combinations require contrast review, including forced-colors and high-contrast modes.

## Type roles

Use the platform system sans stack throughout. A semibold, compact record heading anchors the reference ID and current status; regular text carries questions, disclosure, and explanations; system monospace is reserved for the reference ID and short provenance labels. Sentence case and plain verbs keep the civic tone direct. The restricted monospace role distinguishes record metadata without importing a font.

## Layout rhythm

The submission journey uses a single reading column with 24–32 px section intervals and 8 px label-to-control spacing. Category comes first, followed by approximate text location, description, optional photo presence, privacy disclosure, and a distinct review-and-submit block. After submission, the hierarchy changes: reference and current status lead, supplied history follows on the record spine, and the correction route closes the page. At wider widths, explanatory material occupies a quieter adjacent column; it never interrupts field order.

## Signature element

The “stewardship spine” is a vertical rule with rectangular record tabs. Its first tab holds current status, later tabs hold only supplied history, and an outlined amendment tab ends at “Request a correction.” Solid, dotted, and interrupted rules distinguish recorded progress, unavailable information, and recovery without relying on hue. A line illustration of a shared-garden notice board may occupy unused wide-screen margin outside the task path; it disappears when space is constrained and carries no meaning.

## States and responsive behavior

At 320 px, fields, notices, actions, and spine tabs form one full-width sequence; no horizontal scrolling is intended. Across layouts, status remains above history. Long descriptions and reference IDs wrap or scroll within bounded text treatment without covering actions. Upload failure appears beside the photo control with a retry route; submission failure appears at the submit block with a clear next action. Because persistence is unspecified, failure copy must not promise saved input. Focus returns to the relevant error summary or control according to implemented behavior. Status changes do not animate.

## Accessibility intent

Use native controls, persistent labels, programmatic descriptions, logical headings, and an error summary linked to affected fields. Focus is a two-part outline visible against light, dark, and status surfaces. Icons repeat text rather than replace it. Privacy disclosure is readable before submission, not hidden in a tooltip. Approximate location remains text-only; no map interaction or precision is implied. Target sizing, zoom, reflow, keyboard order, contrast, screen-reader output, and forced-colors behavior need implementation review against WCAG 2.2 AA intent; this direction is not a conformance claim.

## Traceability

Status-first hierarchy and the spine trace to the charter. Category, approximate location, description, photo presence, disclosure, reference, status, supplied history, correction, and failures trace to the stated journey and content. System typography, responsive bounds, no map, visible focus, non-color status encoding, and asset/package limits trace to Fixed constraints. Palette, hierarchy, layout, and the optional notice-board illustration use only the named Open axes. No precedent, external asset, or sibling direction informed this proposal.

## Limitations

This is a visual direction, not a prototype, usability finding, accessibility validation, or certification. The brief supplies no actors, timestamps, retention rules, correction permissions, or persistence guarantees; the interface must omit or mark them undefined until approved. History density, localization, photo constraints, failure causes, and correction outcomes remain uncertain. Representative-user, accessibility, privacy, and content review, responsive implementation, and measured contrast checks are still needed.
