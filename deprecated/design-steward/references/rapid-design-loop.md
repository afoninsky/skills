# Rapid visible design loop

Use this algorithm only in **Autonomous design** after the Owner Design Brief is confirmed, G1 has zero Blocking Unknowns, and G3 is ready. It maximizes useful visual feedback per unit of active time, context, and token budget. It does not relax authority, content truth, safety, privacy, or provenance boundaries. It changes when design and assurance work happen.

## Default latency and iteration budgets

Record a different target when the commission warrants it. Otherwise use:

- **No-blocker readiness overhead:** when supplied inputs already satisfy the brief and the named approval is real, spend no more than 10 active minutes or 10% of the design budget normalizing, validating, and freezing G1/G3. Use one brief, one validator run, and the minimum baseline/charter records. If readiness is not possible, return one consolidated blocker list instead of doing speculative preparation.
- **First visible artifact:** within 15 minutes of active work after direction generation becomes authorized or before consuming 15% of the generation budget, whichever comes first. For a ready-input commission, target no more than 25 active minutes from task start.
- **First comparable contact sheet:** show the six low-fidelity territory sketches before 25% of the generation budget is consumed.
- **Visible iteration share:** spend at least 50% of the preselection design budget creating, inspecting, and improving rendered work.
- **Preselection revision cap:** at most two bounded revision loops per direction before it must be promoted, pivoted, or rejected.
- **Agent topology:** no delegation for raw concepts or territories. Add at most one isolated author per developed direction and one non-author critic only when a named decision risk makes their independence valuable. Do not add pairwise critics, audit agents, or recheck agents.
- **Brief assurance:** one deterministic validator run plus Steward review. Add an independent G1 audit only for a named high-risk ambiguity that deterministic and direct review cannot resolve.

Active time excludes waiting for required human approval. If a richer artifact cannot meet the target, show a lower-fidelity rendered frame, sketch, or concept board. “Still researching” is not a substitute for visible progress after generation is authorized.

## Visible checkpoint sequence

1. **Raw concepts — private and cheap.** Generate 12–15 concise concepts and reject weak ones. Do not write code, full rationales, or durable records.
2. **Six territories — visible.** Form six materially distinct territories and render one matched low-fidelity sketch for each. Show the six-up contact sheet, then continue autonomously unless feedback reveals a consequential owner decision.
3. **Three developed frames — visible.** Render one realistic representative frame per selected direction and inspect it before rationale or code.
4. **Decisive thin slice — visible.** Build the core act and immediate consequence only for surviving directions. Show matched captures as soon as they render.
5. **One revision wave — visible.** Apply the strongest concrete critique within the two-loop cap. Show updated matched captures.
6. **One-backbone G4 set.** Converge on the strongest coherent direction or approved synthesis and add only the responsive/recovery evidence needed for the decision.
7. **Selected-direction assurance.** Expand behavioral coverage, hostile states, accessibility work, technical evidence, and the implementation contract only after convergence.

A visible checkpoint is not an extra approval gate. Use commentary and direct artifact links so the System Owner can observe or interrupt while authorized reversible work continues. Do not withhold all visuals until every direction, state, rationale, and record is complete.

## Fail-fast direction algorithm

For each direction:

```text
frame = render(first meaningful state with realistic content)
if core act is not visible in ten seconds: pivot or reject
if relabel/default-cluster test fails: revise once
if direction is structurally or visually redundant: replace it

slice = render(core act -> immediate consequence)
if interaction thesis is not clearer than the frame: reject
if the slice still fails the quality floor after revision loop 2: reject

only then add mobile, recovery, comparison states, and rationale depth
```

Do not debug a deep state machine, perfect hostile fixtures, or write a comprehensive rationale for a direction that has not passed its frame and thin-slice reviews. A failed thesis is cheaper to replace than to remediate.

## Checks by fidelity

Run the smallest checks that can invalidate the current artifact. Defer the rest explicitly.

| Fidelity | Required now | Explicitly defer |
| --- | --- | --- |
| Hypothesis | Product relevance, scope, core act, structural independence | Code, responsiveness, accessibility mechanics, hostile states, provenance packaging |
| Static frame / concept board | Screenshot opens, realistic content, first-ten-seconds hierarchy, relabel/default-cluster/silhouette review, no review chrome | Full interactions, keyboard path, 200% text, reduced motion, long history, errors, exhaustive responsive states |
| Interactive thin slice | Main action and consequence work, no blocking console error, representative desktop render, one narrow overflow check, visible focus on the main path | Full browser matrix, exhaustive keyboard/AT, all hostile states, deep persistence/recovery, instrumentation, complete rationale |
| G4 survivor | Matched entry/core-act/consequence captures, representative mobile behavior, one material recovery path, basic semantics and keyboard flow, content/capability truth, quality and sameness verdict | Production feasibility, full WCAG assurance, complete privacy/security review, exhaustive data migration, performance/load, all regression states |
| Selected direction / G5 | Full implementation-contract coverage, responsive and hostile states, semantics, keyboard/focus, zoom/reflow, motion, content/data rules, recovery, instrumentation, technical and specialist checks | Only checks explicitly outside the approved implementation or release scope |

Hard-gate evidence is risk-proportionate. Never ignore a known critical violation. Do not require final implementation assurance from a disposable preselection frame.

## Work that must wait

Unless the decision specifically depends on it, do not perform these before a direction survives the thin-slice quality review:

- exhaustive state matrices or every content permutation;
- long-history or large-fixture replays;
- 200% text, reduced-motion, assistive-technology, and multi-browser suites on every draft;
- direct-file portability when the documented review path is a local server;
- artifact hashing, freeze manifests, provenance packets, and full rationale pages;
- pairwise cross-critiques and separate remediation/recheck agents;
- implementation-contract, API, persistence, migration, telemetry, or production feasibility detail;
- repeated checks unaffected by the latest change.

Run cheap mechanical checks alongside rendering when possible. A check that cannot change the current promote/pivot/reject decision is premature.

## Efficient delegation and context

- Send each author one immutable baseline path plus its charter; do not paste the full brief and records into repeated prompts.
- Verify shared specialist availability, version/hash, permissions, and tool access once per generation wave; link each delegation to that result instead of repeating unchanged checks.
- Require the first author return to be the visible frame and concise decision notes, not a completed direction package.
- Continue with the same isolated author for at most two preselection revisions.
- Do not delegate raw-concept or territory generation. If developed directions have isolated authors, join them once for the three-frame contact sheet. Use a fresh non-author critic only when a named risk makes independent critique material and only after the Steward removes obvious failures.
- Keep returns short: artifact links, screenshots, verdict, concrete issues, next change, and material limitations.
- Do not narrate unchanged agent status. Update the user when a visible artifact, material finding, gate, or blocker changes.
- Store one current screenshot per required checkpoint; replace disposable intermediates rather than accumulating evidence files.
- When only an operating plan is possible because product inputs or renderable artifacts are absent, keep it under 600 words by default and state only the mode, four funnel stages, delegation rule, implementation boundary, and exact next action. Do not replay the complete gate or assurance catalog.

## Budget alarms and recovery

Stop and correct the workflow when any alarm fires:

- **15% spent with no visible artifact:** stop research, records, and deep checks; render the lowest useful fidelity now.
- **25% spent with no comparable contact sheet:** reduce artifact fidelity or direction breadth while preserving the approved final count.
- **More than two revision loops on one direction:** promote only if Strong; otherwise pivot or reject.
- **Any agent used for raw concepts or territories, or more than three authors plus one justified critic before selection:** cancel avoidable delegation and consolidate with the Steward.
- **More time on assurance than visible iteration before G4:** defer non-decision-critical checks to the selected direction.
- **User feedback rejects the thesis:** retire its unfinished proof machinery; do not repair states that no longer matter.

At each visible checkpoint, record only: time/budget consumed, artifact link, verdict, decision gained, and next highest-value change. This is enough to learn and continue.
